# 지원포유 콘텐츠 스튜디오

> "제미나이, 클로드 등 AI 도구 소개 및 기본사용법부터 1인 가구·프리랜서·직장인이 활용하는 방법을 지원포유에서 알려드립니다."

구글 블로거 · 네이버 블로그용 **돈 되는 주제 발굴 → 원고·이미지 생성 → 비공개 발행 → 사람 검수 → 공개 발행 → 카드뉴스·SNS 확산 → 유입·수익 분석 → 발전 제안**까지 한 대시보드에서 처리하는 시스템입니다.

```
 ┌──────────┐   ┌──────────────┐   ┌─────────────┐   ┌──────────┐   ┌──────────┐
 │ 주제 발굴 │ → │ 원고+이미지  │ → │ 비공개 발행 │ → │ 사람 검수 │ → │ 공개 발행 │
 │ (점수화)  │   │ SEO/AEO/GEO  │   │ 블로거 초안 │   │ 체크리스트│   │          │
 └──────────┘   │ 자동 점검    │   │ 네이버 비공개│   │ 편집·승인 │   └────┬─────┘
       ▲        └──────────────┘   └─────────────┘   └──────────┘        │
       │                                                                  ▼
 ┌──────────┐   ┌──────────────────────────┐   ┌────────────────────────────────┐
 │ 발전 제안 │ ← │ 유입·수익 분석            │ ← │ 카드뉴스 → 인스타·스레드·페북  │
 └──────────┘   │ GA4·서치콘솔·애드센스·CSV │   └────────────────────────────────┘
                └──────────────────────────┘
```

## 주요 기능

| 영역 | 내용 |
|---|---|
| **주제 발굴** | 자동완성은 후보 제안용, 수요 검증은 공식 데이터(네이버 검색광고 검색량·광고경쟁도, 데이터랩 트렌드, 블로그 문서 수)로. 키워드마다 **검증 수준(공식데이터 확인/자동완성 확인/미검증)** 과 **확인된 지표 수**를 표시하고, 모르는 지표는 숫자를 지어내지 않고 **"미확인"** 으로 둡니다. 점수는 **우선순위 정렬용 내부 지표이며 수익 예측이 아닙니다.** 표기만 다른 키워드는 하나로 합치고, 같은 계정에 같은 키워드 원고는 중복 생성하지 않습니다 |
| **실시간 트렌드 발굴** | 네이버 모바일 홈판·네이버 랭킹·네이트 실시간·구글 트렌드·다음 뉴스·구글 뉴스 **6개 채널**을 브라우저로 수집 → 같은 사건을 다룬 항목을 하나의 소재로 묶어 **교차검증** → 참여 채널 수·신선도·네이버 랭킹·조회수·트렌드 급등률로 점수와 **근거 문장** 생성 (별도 도구 contents-finder 를 포팅). 네이버 블로그 **32개 카테고리**로 분류하고 부정 사건·정치 이슈는 제외, 고른 카테고리의 추천 소재만 저장. 방금 감지한 실시간 트렌드라 **검색량·경쟁도는 검증 데이터가 아직 없어 미확인** |
| **검색어 기반 롱테일 발굴** | 입력한 키워드를 줄여 가며 자동완성·"함께 많이 찾는"·검색광고 연관을 모으고, 메인 키워드를 포함한 롱테일만 남김(월검색량 30 미만 제외, AI 로 같은 주제인지 확인). 고른 키워드에서만 상위 글·AI 브리핑을 벤치마킹해 **제목 6가지 유형** 생성 |
| **황금키워드** | 시드 없이 검색광고 업종 키워드 약 14만 개를 검색량 **7구간**(초보자 100~500 … 레전드 50만+)으로 나눠 비율(문서수÷검색량) 낮은 순으로 표시. 문서수는 블로그 섹션 검색 화면 값(공식 API 월 한도 보호), 최근 30일 발행·수요 성격·AI 블로그 적합 판정·골든 점수(규칙). 매일 새벽 자동 + 버튼 |
| **제목 규칙** | 연도·회차는 **실제로 검색되는 형태·어순일 때만**(검색광고로 확인, 예: "2026 근로장려금"), 월·일·"기준"은 본문에만. 글 수명(상시·해마다 반복·이슈형)별 전략, 고른 제목은 원고 제목으로 **확정**(사실과 어긋날 때만 이유와 함께 변경), 여러 계정은 서로 다른 보조 검색어로 구별. **제목 체크리스트 4**(검색어·내년에도 검색할까·문제 해결·구매 단계 말)를 토큰 없이 자동 점검 |
| **원고 생성** | Claude(기본) 또는 Gemini. 작성 전 **웹 검색으로 최신 요금제·기능 조사**. 검색의도(정보탐색·탐색·상업조사·구매의도)별 **글 유형 레시피**(사용법·튜토리얼·개념·비교추천·후기·구매가이드). **확인 안 된 고유명사·수치 날조 금지, 시제 왜곡 금지.** AI는 경험을 지어내지 않고 **[경험 추가] 자리표시**만 남깁니다(비워 두면 발행본에서 자동 제거) |
| **고위험 주제** | 세무·정부지원·청약·투자·금융·법률·건강 주제를 감지하면 공식 출처 필수, 예측·보장 표현 점검, 고지 문구 자동 삽입. **투자·재테크(INVEST)** — 주식·종목뿐 아니라 실적발표·배당·공시·목표주가·시가총액만 있어도 감지 — 는 "투자 권유 아님·책임은 본인" 고지가 **발행될 HTML에 실제로 있는지** 점검하고, 예측·추천("지금이 매수 시점") 금지, FAQ에서 매수·매도를 대신 판단하지 않는지 점검 |
| **크로스플랫폼 재발행** | 원고 화면의 **"🔁 다른 계정으로 재발행"** (또는 직접 입력 폼의 "재발행 원본")으로 블로거 글을 네이버용 등으로 다시 씀. 원본의 **제목·소제목·핵심만** 전달하고 "복사 금지·관점/구성/예시 새로 쓰기" 규칙 적용, **원본 링크를 자연스러운 백링크로 자동 삽입**, 원본과 35% 이상 비슷하면 경고. 계정 관리에서 **재발행 짝 계정** 지정 가능 |
| **애드포스트 통합 정산** | 네이버 2·3번째 계정을 1번 계정 애드포스트의 미디어로 묶은 구조를 반영 — 계정 관리에서 **애드포스트 정산 계정** 지정 시 그룹 수익을 합산 후 **조회수 비중으로 배분**해 계정별 RPM 계산 |
| **계정 콘셉트 점검** | 콘셉트가 비어 있으면 원고 생성·승인 시 경고, 같은 플랫폼 계정끼리 콘셉트가 겹치면 경고(재발행 짝은 예외). `npm run check:concepts -- "키워드" "콘셉트A" "콘셉트B"` 로 실제 차별화 확인 |
| **시제 모순 점검** | 이미 지난 날짜나, 원고 작성 때 저장한 **조사 메모에 "출시됐다"고 나온 대상**을 본문이 "출시 예정"으로 쓰면 경고 (발행 전 마지막 방어선) |
| **SEO·AEO·GEO** | 상단 직답·핵심요약·질문형 소제목·FAQ(AEO), 기준일·공식 출처·비교표·프롬프트 예시·저자 엔티티(GEO), 키워드 배치·분량·이미지 alt·메타 설명(SEO). 블로거에는 **Article/FAQPage 구조화 데이터**·목차 자동 삽입. **자동 점검 점수** 제공. FAQ·메타·직답의 첫 문장이 단독 인용돼도 뜻이 통하는지(AEO) 검사. 분량·이미지 수·태그 수는 공식 규칙이 아니므로 **"참고" 그룹**(점수 영향 작음) |
| **검수 보조** | **AI 사실 검수**(웹검색으로 사실오류·오탈자만 제안, 제목·구조·키워드 보존, 사람이 골라 적용), **섹션 하나만 다시 쓰기**, **승인 전 확인 사항** 요약(결정은 사람), **반려** 상태 |
| **사실성 파이프라인** | 조사(공식 출처 우선·기준일) → 핵심 수치 공식 페이지 대조(Claude 가 403 인 공식 페이지는 스튜디오 브라우저로 원문을 읽어 전달) → 원고(확인된 값만 단정) → 작성 직후 자체 점검. 사람 확인 목록은 실제로 할 일만 남김 |
| **블로그 동기화·기존 글 등록** | 비공개 발행 뒤 블로그에서 직접 고친 내용을 가져와 비교(🌐 블로그 현재본), 덮어쓰기 전 확인. 이미 발행한 글을 등록해 **원고로 변환**(내용 그대로 구조만, 블로그 원본 이미지도 썸네일·섹션 이미지로 연결) → 검수·SEO·카드뉴스·재발행 |
| **이미지** | 썸네일(제목 합성, 네이버는 1:1) + 본문 이미지: 공식 사이트 **화면 캡처**, Gemini **AI 이미지 생성**, Unsplash/Pexels **스톡 검색**, 실패 시 브랜드 템플릿. 검수자가 **직접 캡처로 교체** 가능 |
| **발행** | 1단계: 블로거 **초안(isDraft)** / 네이버 **비공개 발행 또는 임시저장** → 2단계: 사람 승인 후 공개. 블로거는 공식 API, 네이버는 Playwright 브라우저 자동화 |
| **유사문서 방지** | **같은 플랫폼 안에서** 원고 간 유사도 계산, 35% 이상이면 경고 (블로거·네이버용으로 각각 다시 쓴 원고는 정상이므로 비교하지 않음) |
| **수익화** | 애드센스 인아티클 광고 슬롯 자동 삽입(블로거), 쇼핑커넥트·쿠팡파트너스 상품 라이브러리 → 관련 있을 때만 1~2개 자연 삽입 + **대가성 문구 자동 표기** |
| **카드뉴스** | 원고 → 7장 카드뉴스(1080×1350) + 인스타·스레드·X·페이스북·밴드용 캡션. 문구 편집 후 재렌더, 테마 3종. 인스타그램·스레드·페이스북 자동 발행, 그 외는 ZIP |
| **분석** | GA4(글별 조회수), 서치콘솔(클릭·노출·순위·검색어), 애드센스(일별 수익) 자동 동기화. 네이버는 RSS로 공개 여부 확인 + 조회수·애드포스트·쇼핑커넥트 **CSV/직접 입력**. 계정별 RPM |
| **발전 제안** | 규칙 기반(제목 개선·2페이지 글 보강·수익화 누락·카드뉴스 재활용·발행 주기·검수 적체·검색어 공백 → 다음 주제, 광고 밀도 vs 체류시간, 홈판·검색 배분, **연도 갱신·이슈형의 오래 남는 짝 주제·제목 유형별 유입 비교**) + AI 전략 요약. 공개된 글은 **제안만**(자동 수정 없음) |
| **멀티 계정** | 블로거 N개(계정마다 다른 구글 아이디 가능)·네이버 N개·SNS N개. 계정별 콘셉트·광고 설정·분석 설정 |
| **자동화** | 워커가 매주 주제 발굴, 매일 분석 동기화·발전 제안 갱신 (cron 설정 가능) |

## 빠른 시작 (데모 모드 — AI 연결 없이 체험)

필요: **Node.js 22 이상**

```bash
npm install
npx playwright install chromium     # 썸네일·카드뉴스 렌더링, 네이버 자동화용 브라우저
cp .env.example .env                 # 데모로 먼저 보려면 .env 에서 LLM_PROVIDER="mock"
npm run setup                        # DB 생성 + 브랜드 설정·데모 계정·샘플 제휴상품
npm run dev                          # 웹(3000) + 워커 동시 실행
```

http://localhost:3000 접속 → **주제 발굴 → 원고 생성 → 비공개 발행 → 승인 → 공개 발행 → 카드뉴스 → 분석 동기화 → 발전 제안**을 샘플 데이터로 모두 눌러볼 수 있습니다.
`[데모]` 계정은 실제 플랫폼에 발행하지 않고 상태만 바뀝니다.

> 이미 설치된 크롬을 쓰려면 `.env` 에 `CHROMIUM_EXECUTABLE_PATH` 를 지정하면 `playwright install` 없이도 동작합니다.

## 실제 운영 설정

`.env` 에 필요한 키를 넣고 재시작하면, 키가 있는 기능부터 자동으로 실제 모드로 바뀝니다. 대시보드 **[설정]** 에서 연동 상태를 확인할 수 있습니다.

### 1) 글쓰기 AI — 추가 요금 없이 (권장)

API 키 방식(`ANTHROPIC_API_KEY`)은 **Claude 구독(Pro/Max)과 별개로 사용량만큼 과금**됩니다. 이미 구독 중이라면 아래 조합으로 API 요금 0원 운영이 가능합니다.

| 작업 | 기본 담당 | 비용 |
|---|---|---|
| 원고·섹션 다시 쓰기·AI 사실 검수 | **Claude Code (구독 로그인)** | 추가 요금 없음 · 구독 사용 한도 사용 |
| 최신 정보 조사 (웹 검색) | **Claude Code (구독)** | 〃 |
| 주제 기획 문구·카드뉴스·발전 제안 요약 | **로컬 Ollama** (예: `gemma4:12b`) | 무료 · 무제한 |
| 구독 한도 초과·미설치·오프라인 | **수동 모드** 자동 전환 | 무료 (지시문 복사 → 데스크탑 Claude → 결과 붙여넣기) |
| (선택) API 키 | Claude / Gemini API | 사용량만큼 과금 |

**Claude Code (구독) 설정** — 맥미니에서 한 번만
1. https://claude.com/claude-code 안내대로 설치 → 터미널에서 `claude` 실행 → `/login` → **구독 계정(Claude.ai)** 으로 로그인
2. `npm run check:ai` → "구독 로그인으로 응답 성공" 이 나오면 끝
- 이 프로그램은 Claude Code 를 실행할 때 `ANTHROPIC_API_KEY` 등 API 과금 경로의 환경변수를 **자동으로 빼고** 실행합니다(키가 `.env` 에 있어도 구독으로만 동작).
- 원고 작성 때는 Claude Code 의 도구(파일·명령 실행)를 모두 끄고, 조사 때만 웹 검색·웹 페이지 읽기를 허용합니다. 빈 임시 폴더에서 실행해 프로젝트 파일을 건드리지 않습니다.
- 구독 한도는 데스크탑 앱·Claude Code 와 **함께** 씁니다. 원고 1편 ≈ 조사 1회 + 작성 1회. 한도를 아끼려면 `CLAUDE_CODE_MODEL=sonnet`(기본) 유지.

**Ollama (로컬) 설정**
1. https://ollama.com 설치 → `ollama pull gemma4:12b` (이미 있으면 생략)
2. Ollama 앱이 켜져 있으면 가벼운 작업이 자동으로 로컬로 갑니다. 24GB 메모리 기준 `OLLAMA_NUM_CTX=16384` 권장.
- 로컬 12B 모델은 웹 검색이 안 되고 긴 원고에서 규칙 누락이 생기기 쉬워 **원고 본문은 맡기지 않는 것**을 권장합니다(원하면 `LLM_WRITE=ollama`).

**수동 모드** — Claude Code 가 없거나 한도가 찼을 때
- AI 가 필요한 단계에서 작업이 멈추고 **✋ 수동 작업함**(`/manual`)과 원고 화면에 카드가 뜹니다.
- **📋 지시문 복사** → 데스크탑 Claude 에 붙여 넣기(웹 검색 켜기 권장) → 받은 답을 그대로 **결과 붙여넣기**. 앞뒤 설명·코드블록이 섞여도 JSON 만 골라 검증하고, 틀린 곳은 한국어로 알려 줍니다.
- 붙여 넣으면 이미지·점검·비공개 발행 준비는 자동으로 이어집니다.

**작업별 지정** — `.env` 의 `LLM_WRITE` · `LLM_RESEARCH` · `LLM_LIGHT` (`claude-code | ollama | manual | anthropic | gemini | mock`), 실패 시 전환 `LLM_FALLBACK`(기본 manual).
비워 두면 자동: Claude Code 설치됨 → 구독, Ollama 실행 중 → 가벼운 작업은 로컬, 둘 다 없으면 API 키 → 수동. 대시보드 **[설정] → AI 담당 · 비용**에서 현재 배정과 연결 상태를 확인할 수 있습니다.

- 이미지는 화면 캡처·무료 스톡(Unsplash/Pexels)·템플릿으로 만들어 0원입니다. `GEMINI_API_KEY` 를 넣은 경우에만 AI 이미지 생성을 씁니다.

**실시간 트렌드 발굴 (키 필요 없음)** — [주제 발굴] 화면의 **📡 실시간 트렌드에서 발굴**

- 제목·구성안은 기존 AI 라우팅(구독 Claude Code / 로컬 Ollama / 수동)으로 한 번에 만듭니다.
- 매일 자동 실행: `.env` 의 `CRON_CHANNEL_DISCOVERY="50 7 * * *"`, `CHANNEL_DISCOVERY_CATEGORY="비즈니스·경제"`.
- 사이트 화면이 바뀌어 0건이 나오면 `npm run channels:check` 로 채널별 상태를 확인하세요(🌐 접속 불가 / ❌ 선택자 문제 구분).

### 3) 구글 블로거 · GA4 · 서치콘솔 · 애드센스

> 블로거 API 로는 **검색 설명(메타 설명)** 을 넣을 수 없어, 검수 화면의 메타 설명을 블로거 편집기의 "검색 설명"에 붙여 넣어 주세요.

### 7) 개발·디버깅용 MCP (선택 — 맥미니의 Claude Code 에서만)

프로젝트 폴더에서 `claude` 를 실행하면 `.mcp.json` 의 MCP 서버가 뜹니다(처음 한 번 승인). 앱 실행과는 무관하고, **Claude Code 가 실제 화면·데이터를 보면서 고칠 수 있게** 하는 도구입니다. 사용 절차는 `CLAUDE.md` 에 있습니다.

| 서버 | 하는 일 | 준비 |
|---|---|---|
| `jk-biz` (이 저장소, 읽기 전용) | DB 현황·원고 점검 결과·작업 로그·수동 대기 목록, **서치콘솔·애드센스·GA4 를 API 에서 받아 DB 동기화 값과 비교**, 네이버 선택자 점검 | 없음 (대시보드에서 구글 연결한 토큰 사용) |
| `playwright` (Microsoft 공식) | 실제 브라우저로 네이버 에디터를 열어 선택자 확인 | 처음 한 번 그 브라우저에서 네이버 로그인 (프로필 `storage/naver/mcp-profile`, git 제외) |
| `analytics-mcp` (Google 공식 GA4, 읽기 전용) | GA4 보고서 직접 조회 | `brew install pipx` → Cloud Console 에서 Analytics Admin·Data API 사용 → `gcloud auth application-default login --scopes https://www.googleapis.com/auth/analytics.readonly,https://www.googleapis.com/auth/cloud-platform --client-id-file=<OAuth 클라이언트 JSON>` → `~/.zshrc` 에 `export GOOGLE_PROJECT_ID=<프로젝트ID>` |
| `prisma` (공식) | 스키마 확인·Prisma Studio | 없음. migrate-reset/migrate-dev 는 쓰지 마세요(이 프로젝트는 db push) |

- 서치콘솔·애드센스는 구글 공식 MCP 가 없어, 신뢰도가 제각각인 커뮤니티 서버 대신 `jk-biz` 가 앱과 같은 코드로 조회합니다.
- 네이버 화면이 바뀌어 자동 발행이 실패하면: `npm run naver:check -- <계정ID>` → 미발견 항목 확인 → Claude Code 에 "네이버 선택자 고쳐줘" (Playwright MCP 로 화면 확인 후 `SELECTORS` 수정).
- 이 MCP 들은 로그인·인증이 필요한 맥미니에서만 동작합니다(클라우드 세션에서는 확인 불가).

## 여러 계정 운영 팁
- **재발행 짝**: 블로거(AI 활용) ↔ 네이버(AI 재발행)처럼 의도적으로 같은 주제를 공유하는 계정은 [계정 관리]에서 서로 "재발행 짝"으로 지정하세요. 블로거 글을 먼저 공개 발행한 뒤 "다른 계정으로 재발행"을 누르면 원본 링크가 백링크로 들어갑니다.
- **애드포스트 묶음**: 네이버 2·3번째 계정의 [계정 관리]에서 "애드포스트 정산 계정"을 1번 계정으로 지정하고, 애드포스트 수익은 1번 계정으로 입력하세요.
- 계정마다 **콘셉트를 다르게** 쓰세요 (예: 네이버A = 직장인 업무 자동화, 네이버B = 1인 가구 생활 AI, 네이버C = 프리랜서 수익화). 같은 주제로 여러 계정 원고를 만들면 콘셉트에 맞춰 다른 관점으로 작성되며, 같은 플랫폼 안에서 유사도 35% 이상이면 경고합니다.
- 같은 주제를 여러 네이버 계정에 **같은 날 동시에** 올리는 것은 피하세요.
- 블로거는 계정마다 다른 구글 아이디로 연결할 수 있습니다.

## 배포
- 워커(Playwright 포함)가 항상 돌아야 하므로 **상시 켜진 PC 또는 VPS**(예: 2vCPU/4GB)에 `npm run build && npm start` 로 운영하세요.
- 운영 DB 는 PostgreSQL 권장: `prisma/schema.prisma` 의 provider 를 `postgresql` 로 바꾸고 `DATABASE_URL` 변경 후 `npm run db:push`.
- 네이버 로그인(`naver:login`)은 화면이 필요하므로 로컬 PC에서 실행한 뒤 `storage/naver/<계정ID>.json` 을 서버로 복사해도 됩니다.

## 알려진 제약 · 주의사항
- **네이버 자동화는 실제 네이버 계정으로 검증이 필요합니다.** 네이버 에디터 구조가 바뀌면 `src/lib/publishers/naver.ts` 의 `SELECTORS` 를 수정해야 할 수 있습니다. 실패해도 원고는 남아 있으므로 [HTML 코드]를 복사해 수동 발행 후 **[직접 발행함으로 표시]** 를 누르면 분석이 이어집니다.
- 네이버 블로그 통계·애드포스트·쇼핑커넥트는 공개 API 가 없어 **CSV/직접 입력**으로 반영합니다.
- AI 원고는 초안입니다. 대량 자동 발행은 네이버 저품질·구글 스팸 정책 위험이 있어 **사람 검수 후 공개**하도록 설계했습니다 (승인 없이 공개 발행 불가).
- 주제 점수는 우선순위 정렬용이며 수익을 보장하거나 예측하지 않습니다. 네이버 API 키가 없으면 대부분의 지표가 "미확인"으로 표시됩니다.
- AI 도구의 요금·기능은 자주 바뀝니다. 원고의 `reviewChecklist` 와 출처를 꼭 확인하세요.
